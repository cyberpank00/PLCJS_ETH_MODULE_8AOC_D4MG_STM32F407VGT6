# PLCJS_ETH_MODULE_8AOC_D4MG_STM32F407VGT6

Прошивка Ethernet-модуля PLCJS с 8 аналоговыми токовыми выходами 0–20 mA
(4–20 mA NAMUR) на базе `STM32F407VGT6`. Выход типа **source**: модуль сам
питает токовую петлю от изолированного источника 24 В.

Модуль формирует 8 каналов тока одним 16-битным ЦАП `DAC80508` и восемью
преобразователями U/I `XTR111`, публикует состояние по `Modbus TCP`, хранит
настройки и **уставки при включении** во внутренней Flash, а калибровку — в
отдельном одноразово записываемом (write-once) секторе Flash, поддерживает
поведение при потере связи (HOLD / SAFE / OFF), управляет главным индикатором
`STAT_LED` и восемью канальными светодиодами, factory reset и OTA через
Ethernet bootloader.

MAC-адрес уникален для каждого изделия: он детерминированно выводится из
96-битного уникального ID кристалла `STM32`.

Базовая архитектура (сеть, многоклиентный Modbus TCP, настройки, LED,
bootloader/OTA, write-once калибровка, компактная карта регистров)
унаследована от варианта `8AIC`.

## Аппаратная платформа

| Узел | Описание |
|---|---|
| MCU | `STM32F407VGT6`, Cortex-M4F |
| Ethernet | `KSZ8863` switch/PHY, RMII |
| ЦАП | `DAC80508ZRTET` — 8×16 бит, встроенная опора 2.5 В, выход 0…2.5 В, ноль при включении |
| Преобразователи U/I | 8× `XTR111AIDGQR`, `R_SET = 1.1 kΩ 0.1 % 10 ppm` → `I = 10·V/R_SET`, 0…22.7 mA |
| Управление/статусы XTR111 | расширитель `MCP23S17` (SPI): ON — включение выхода, EF — флаг ошибки |
| Изоляция | цифровая `CA-IS3741` / `CA-IS3722`; питание `URB2424S-6WR3` (24 В → 24 В изол.), вход CTRL на MCU |
| Питание петли | 24 VDC изолированное; ЦАП и расширитель питаются от той же шины |
| Температура MCU | внутренний датчик (`ADC1_IN16`) |
| Factory reset | кнопка `FACT_RES`, active-low (также подтверждает аварийный сброс калибровки) |
| Индикация | `STAT_LED` + 8 канальных светодиодов |
| Watchdog | `IWDG` |

### Распиновка

| Сигнал | Пин | Сигнал | Пин |
|---|---|---|---|
| SPI1 SCLK | PA5 | SPI1 MISO | PA6 |
| SPI1 MOSI | PB5 | | |
| DAC_CS | PA12 | MCP_CS | PD8 |
| PVD_CTRL | PB7 | | |
| AO0_STAT | PB15 | AO1_STAT | PB14 |
| AO2_STAT | PB10 | AO3_STAT | PE15 |
| AO4_STAT | PE14 | AO5_STAT | PE13 |
| AO6_STAT | PE12 | AO7_STAT | PE11 |
| STAT_LED | PE9 | FACT_RES | PE10 |
| ETHRST | PD11 | ETHINT | PB1 |

SPI: master, 8-бит, MSB first, ~2.6 МГц; режим переключается на каждую
транзакцию — **mode 1** для DAC80508, **mode 0** для MCP23S17.

MCP23S17 (адрес 0): `GPA0/1` AO3 EF/ON, `GPA2/3` AO5, `GPA4/5` AO6, `GPA6/7` AO7;
`GPB0/1` AO4 ON/EF, `GPB2/3` AO2, `GPB4/5` AO1, `GPB6/7` AO0. EF — открытый
сток с подтяжкой 10k, **низкий уровень = ошибка**.

### Порядок включения аналоговой части

ЦАП и расширитель питаются от изолированной шины, поэтому при старте:
`PVD_CTRL → ON` → пауза 150 мс → soft-reset и конфигурация DAC80508
(gain ×1, все выходы 0) → конфигурация MCP23S17 (все каналы OFF) → уставки
при включении. Если ЦАП или расширитель перестают отвечать (5 опросов подряд),
прошивка автоматически передёргивает питание шины (не чаще раза в 10 с) и
переинициализирует их; то же можно сделать вручную — `HR118 = 0xA0FF`.
На время цикла (~0.7 с) все выходы — 0 mA.

Полярности `PVD_CTRL` (`PVD_CTRL_ON_LEVEL` в `main.h`) и линий ON
(`MCP23S17_ON_ACTIVE_HIGH` в `mcp23s17.h`) — константы, проверяются на плате.

### Канальные светодиоды

- **горит постоянно** — канал включён и выход активен;
- **не горит** — канал выключен (или выход снят режимом OFF при потере связи);
- **быстро мигает (5 Гц)** — ошибка: EF от XTR111 (обрыв петли / выход из
  диапазона / перегрев), расширитель или ЦАП не отвечают, шина петли выключена.

## Уставка и шкала канала

Уставка задаётся двумя способами (действует последняя запись):
- `HR 0 + ch` — int16 `0..32767` ↔ `[нижний порог … верхний порог]` (дефолт
  4000…20000 µA); отрицательные значения — кламп в нижний порог;
- `HR 48 + ch` — напрямую в µA, `0..22000`.

Уставка применяется немедленно (≤ 10 мс); `SAVE` (HR117) сохраняет текущие
уставки как **значения при включении**.

## Поведение при потере связи

Если ни один Modbus-клиент не прислал корректный запрос за таймаут
`HR100` (×100 мс, дефолт 50 = 5 с; 0 = выключено), для каждого канала
применяется режим `HR 32 + ch`:

| Режим | Действие |
|---|---|
| 0 HOLD (дефолт) | удерживать последнюю уставку |
| 1 SAFE | выдать `HR 40 + ch` µA (например 3600 — NAMUR fail-low, 21000 — fail-high) |
| 2 OFF | снять выход (0 mA, XTR111 выключен) |

При появлении запроса уставки восстанавливаются автоматически. Отсчёт
идёт с момента старта — если мастер не подключится за таймаут, сработает
защитный режим.

## Калибровка

Каждый канал корректируется по 2-точечной линейной модели
`I_cmd = gain × I_set + offset`: при нейтральных коэффициентах выставляются
уставки, ток измеряется эталонным амперметром, инструмент в `tools/` считает
и записывает коэффициенты. Затем — **write-once COMMIT** (`HR131 = 0xCA00 | ch`),
8 слотов, статус в `IR127`; аварийное стирание — `HR132 = 0xC1A5` + удержание
`FACT_RES` 3 с. Подробности — [tools/README.md](tools/README.md).

## Карта регистров Modbus

float32 — два регистра, **старшее слово первым**. Многоканальные величины
сгруппированы по величине: 8 регистров (или пар) подряд — каналы 0..7.

### Компактный блок — Holding Registers (FC03/06/16), 0..55

| Рег | Описание |
|---|---|
| 0..7 | **уставка int16 (RW)**: `0..32767` ↔ `[нижний … верхний порог]` |
| 8..15 | нижний порог шкалы, µA (дефолт 4000; 0..22000, меньше верхнего) |
| 16..23 | верхний порог шкалы, µA (дефолт 20000; до 22000, больше нижнего) |
| 24..31 | enabled (0/1, дефолт 1) |
| 32..39 | режим при потере связи: 0 HOLD, 1 SAFE, 2 OFF |
| 40..47 | safe-значение, µA (дефолт 0) |
| 48..55 | **уставка в µA (RW)**, 0..22000 |

При сдвиге шкалы вверх сначала записывайте верхний порог (пороги проверяются
взаимно).

### Состояние — Input Registers (FC04), 300..333

| Рег | Тип | Описание |
|---|---|---|
| 300..315 | float32 ×8 | командуемый ток, mA (0 при снятом выходе; с учётом подстановки при потере связи) |
| 316..323 | u16 ×8 | флаги: bit0 enabled, bit1 выход активен, bit2 fault, bit3 потеря связи; bits15..8 код ошибки (1 EF XTR111, 2 расширитель не отвечает, 3 ЦАП не отвечает, 4 шина петли выключена) |
| 324..331 | u16 ×8 | код ЦАП 0..65535 |
| 332 | u16 | питание петли включено (0/1) |
| 333 | u16 | потеря связи активна (0/1) |

Глобальные: `120` fw major, `121` fw minor, `122/123` uptime (с), `125`
module id (`0x08A0`), `126` температура MCU (signed 0.1 °C), `127` маска
блокировки калибровки.

### Общие настройки — Holding Registers

| Рег | Описание |
|---|---|
| 100 | таймаут потери связи, ×100 мс (0 = выкл, дефолт 50) |
| 101 | режим LED (0/1/2) |
| 102 | Modbus slave id | 103 | Modbus TCP порт |
| 104..107 | static IP | 108..111 | netmask | 112..115 | gateway |
| 116 | net mode: `0` static / `1` DHCP / `2` link-local (default `2`) |
| 117 | SAVE (`0xA5A5`) — настройки + текущие уставки как значения при включении |
| 118 | REBOOT (`0xB00B`) / BOOTLOADER (`0xB007`) / сброс KSZ8863 (`0x8863`) / **перезапуск аналоговой части (`0xA0FF`)** |
| 119 | FACTORY RESET (`0xDEAD`) | 130 | температура MCU (RO) |
| 131 | CAL COMMIT (`0xCA00 \| ch`) | 132 | CAL ERASE ARM (`0xC1A5`) |
| 133 | период опроса EF / liveness, мс (20..5000, дефолт 100) |

Коэффициенты калибровки (float32), база `540 + ch×4` (**write-once**):
`+0..1` gain, `+2..3` offset (mA). Номиналы: `620..621` R_SET Ω (1100.0),
`622..623` V_REF В (2.5).

## Flash layout

| Область | Адрес | Размер | Назначение |
|---|---:|---:|---|
| Bootloader | `0x08000000` | 128 KB | sectors 0-4 |
| Metadata | `0x08020000` | 128 KB | sector 5 |
| Application | `0x08040000` | 256 KB | sectors 6-7 (эта прошивка) |
| Staging | `0x08080000` | 256 KB | sectors 8-9 |
| Settings | `0x080C0000` | 128 KB | sector 10 |
| Calibration | `0x080E0000` | 128 KB | sector 11 (write-once) |

`SETTINGS_MAGIC = 0x08A04A57`, `SETTINGS_VERSION = 1`. Калибровка: 8 слотов,
magic `0xCA11B0A0`.

## Сборка

```powershell
cmake --preset Debug
cmake --build --preset Debug
```

Идентичность — `Application/fw_header/fw_header.h`: `FW_PRODUCT_ID=0x504C0806`,
`FW_HW_REVISION=0x0101`, `FW_VERSION_VALUE=0x0101`. Результаты в
`build/Debug/`; `.bin` — OTA-образ с `fw_header_t` по смещению `0x200`.

## Прошивка

```powershell
STM32_Programmer_CLI -c port=SWD -w build/Debug/PLCJS_ETH_MODULE_8AOC_D4MG_STM32F407VGT6.elf -v -rst
```

## Сеть (дефолты)

| Параметр | Значение |
|---|---|
| Сетевой режим (`USE_DHCP`) | `2` = link-local (заводской) |
| Заводской адрес | `169.254.<mac[4]>.<mac[5]>` /16, из UID |
| Резервные static-поля | IP `192.168.1.14`, маска `255.255.255.0`, шлюз `192.168.1.1` |
| Modbus TCP порт | `502`, до 4 клиентов одновременно |
| Modbus unit id | `1` |

## Инструменты

`tools/calibrate.mjs` (Node.js 18+) и `tools/calibrate.py` (Python 3.8+) —
статус, конфигурирование, калибровка, перезапуск аналоговой части. См.
[tools/README.md](tools/README.md).

```powershell
node tools/calibrate.mjs status --ip 192.168.1.14
node tools/calibrate.mjs set --ch 0 --ua 12000 --enable 1
node tools/calibrate.mjs calibrate --ch 0
node tools/calibrate.mjs cycle
```
